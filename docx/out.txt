Task: Standalone Flutter IT Assets Management
App with Odoo XML-RPC

Assigned To

Mostafa Bader

Objective

Develop a professional Flutter mobile application for IT Assets Management integrated directly with
Odoo through XML-RPC.

The application must be a standalone product. It must not require any custom Odoo addon/module
to be installed on the customer's Odoo instance.

The Flutter application itself will contain the business logic, UI, permissions handling, asset workflows,
and XML-RPC integration.

2. Important Standalone Requirement

The application must NOT depend on a Digital Harbor custom Odoo addon.
Do not create something like:

   dh_it_asset_management

on Odoo.
All communication should happen using existing Odoo models and standard Odoo APIs.
The app should contain an Odoo compatibility/service layer so that model names and available fields
can be detected where necessary.
The app should be capable of checking models and fields using Odoo metadata such as:

   ir.model
   ir.model.fields

This prevents the Flutter UI from breaking because a particular optional Odoo application or field is
unavailable.

Acceptance Criteria

The task will be considered complete when:
      1. The app can connect to a normal Odoo instance using only its URL, database, username and
          password/API key.
      2. No custom Odoo addon is required.
      3. The user can log in using Odoo credentials.
      4. Assets can be viewed and managed from Flutter.
      5. Employees can be retrieved from Odoo.
      6. Assets can be assigned and returned.
      7. QR codes can identify assets.
      8. Search and filters work correctly.
      9. Odoo ACLs are respected.

     10. Missing optional Odoo models do not crash the application.
     11. XML-RPC logic is isolated from the Flutter UI.
     12. Credentials are securely stored.
     13. Large datasets use pagination.
     14. The application works as an independent commercial product rather than a companion frontend

          requiring a custom Odoo module.
     15. Code is structured so that additional ERP/Odoo functionality can be added later without

          rewriting the XML-RPC layer.
